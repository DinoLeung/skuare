# Translating Skuare

Thanks for helping translate Skuare. This guide covers adding a new language and improving an
existing one. You only edit XML files, no Kotlin is needed.

Languages so far:

| Language | Code | Folder |
| --- | --- | --- |
| English (base) | `en` | `values` |
| Traditional Chinese (Hong Kong) | `zh-HK` | `values-zh-rHK` |
| Traditional Chinese (Taiwan) | `zh-TW` | `values-zh-rTW` |

## How the app picks a language

The app follows the phone's language, or the app's own language setting (Android 13+:
Settings > Apps > skuare > Language, iOS: Settings > skuare > Language).

Anything that isn't translated falls back to English, so a partial translation is fine and can be
completed later.

Dates, month names and weekday names come from the phone's own locale data, so they need no
translation.

## Pick the folder name

The folder name is `values-` plus the language code:

- A language for every region, e.g. German: `values-de`.
- A language for one region, e.g. Brazilian Portuguese: `values-pt-rBR`, with an `r` before the
  region. Use this when the wording differs between regions, as with Hong Kong and Taiwan.
  The app's screens only use a region folder in that region, e.g. a phone set to Macau (`zh-MO`)
  doesn't get `zh-rHK` there. If one translation suits every region, use the language-only
  folder instead.

The language code you declare in the files below is the same code without the `r`: `de`,
`pt-BR`, `zh-HK`.

Only these two forms are supported. `./gradlew check` doesn't understand script variants such as
`b+sr+Latn`.

## Files for a new language

Say the folder is `values-de` and the code is `de`.

### 1. The app's text (required)

Copy `composeApp/src/commonMain/composeResources/values/strings.xml` to
`composeApp/src/commonMain/composeResources/values-de/strings.xml` and translate the text between
the tags. Keep each `name="…"` as it is. The comments above some strings explain where they show up
and what a placeholder holds. You can delete any string you don't translate yet.

### 2. The notification (required)

Copy `composeApp/src/androidMain/res/values/strings.xml` to
`composeApp/src/androidMain/res/values-de/strings.xml` and translate the four notification
strings. Leave out `app_name`, it is marked `translatable="false"`.

### 3. City names (optional)

The time zone picker and the clocks show city names from two files in
`composeApp/src/commonMain/composeResources/values`:

- `home_timezones.xml`: home cities, keys `home_tz_<id>`
- `world_timezones.xml`: world cities, keys `world_tz_<id>`

Don't edit those two English files, they are generated by the scripts in `data/`. Create
`values-de/home_timezones.xml` and `values-de/world_timezones.xml` with the cities whose name
differs in your language:

```xml
<?xml version="1.0" encoding="utf-8"?>
<resources>
	<string name="world_tz_281">Tokio</string>
</resources>
```

A city you leave out shows its English name. Many cities have the same name in Latin-script
languages, so those files can be short. Languages in another script need every city.

Leave technical zones in English, such as `GMT+5`, `UTC`, `EST` or `CET`. Some home "cities" are
regions from the time zone database, e.g. `Eastern` (US Eastern Time) or `NSW` (New South Wales),
and are best translated as the region. The Chinese files are an example of all of this: they were
seeded from the [Unicode CLDR](https://cldr.unicode.org/) city names and completed by hand. If
you seed names from CLDR too, list your files in [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

### 4. Declare the language (required)

Add the code in three places, so both phones offer it in their language settings:

- `composeApp/src/androidMain/res/xml/locales_config.xml`:
  ```xml
  <locale android:name="de" />
  ```
- `iosApp/iosApp/Info.plist`, in the `CFBundleLocalizations` array:
  ```xml
  <string>de</string>
  ```
- `iosApp/iosApp.xcodeproj/project.pbxproj`, in the `knownRegions` list. Quote codes with a
  hyphen:
  ```
  de,
  "pt-BR",
  ```

## Rules

- **Placeholders.** `%1$s` (text) and `%1$d` (number) are replaced by values when the app runs,
  e.g. `Forget %1$s?` shows `Forget CASIO GW-B5600?`. Keep every placeholder of the English string,
  in any order the sentence needs, and keep their numbers. Never use `%s` or `%d` without a number.
- **Plurals.** A `<plurals>` entry has one `<item>` per plural form of your language, by its
  [CLDR plural category](https://www.unicode.org/cldr/charts/latest/supplemental/language_plural_rules.html):
  English has `one` and `other`, Chinese and Japanese only `other`, Polish `one`, `few`, `many` and
  `other`. `other` is always needed.
- **Apostrophes.** In the `composeResources` files write a plain `'`. In Android's
  `res/values-…/strings.xml` write `\'`, Android's own format needs it.
- **Lists.** `common_list_join` joins two items of a list, e.g. `%1$s, %2$s` in English or
  `%1$s、%2$s` in Chinese. It is applied repeatedly for longer lists.
- **Length.** Some spots are narrow: the tab labels at the bottom, and the DST dropdown in the time
  zone picker (`timezone_picker_dst`, `dst_auto`, `dst_on`, `dst_off`). Prefer a short word there.
- **Watch terms.** Where a term names a watch feature, use the word Casio uses for it in your
  language if you know it, e.g. the snooze alarm or the hourly signal.

Not translated, wherever they show up:

- Watch model names, e.g. `CASIO GW-B5600`.
- What the watch itself shows and stores: reminder titles and the watch's name are typed by the
  user, and the city names sent to the watch stay as the watch knows them.
- The date formats `MM.DD` and `DD.MM`, the watch's own settings.
- The `00h 00m 00s` hint of the timer.

## Check your translation

Run:

```
./gradlew :composeApp:checkTranslations
```

It prints nothing when everything is fine. Otherwise it lists what to fix, for example:

- `… isn't in values/strings.xml`: a key that the English file doesn't have, check its spelling.
- `… has placeholders [], English has [%1$s]`: a placeholder is missing.
- `… use positional placeholders`: `%s` instead of `%1$s`.
- `de has composeResources but is missing from …`: the language isn't declared everywhere, see
  [Declare the language](#4-declare-the-language-required).

`./gradlew check` runs this check too, and CI runs it on every pull request.

If you can build the app, check your text on a phone, set to your language, especially long texts
on small screens.

## Send it

Open a pull request with your files. Commit subjects follow conventional commits, and `feat` and
`fix` subjects end up in the store changelog, so a new language is for example:

```
feat: add German
```

An update to an existing translation can be `fix: improve the German translation`.
